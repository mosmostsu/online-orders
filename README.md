# order-sync

ดึงออเดอร์จากมาร์เก็ตเพลสมารวมไว้ที่เดียว — **เฟส 1: เห็นออเดอร์จริงก่อน** (รอจัดส่ง / จัดส่งแล้ว / ยกเลิก)
ยังไม่แตะสต็อก ยังไม่ push อะไรกลับไปที่แพลตฟอร์ม

ตอนนี้: TikTok Shop (ร้าน SOLID) · ถัดไป: Shopee

## เปิดใช้งาน

**1. Supabase** — สร้าง project ใหม่ → SQL Editor → วางไฟล์ `supabase/schema.sql` ทั้งไฟล์ แล้วรัน
เอา Project URL กับ `service_role` key มาใส่ `.env.local`

**2. ตัวแปรลับ** — `.env.local` (มีให้แล้ว ดึงมาจากสคริปต์ Colab) ต้องเติมแค่ 2 ค่าของ Supabase
ตอน deploy ให้ก๊อปทุกบรรทัดไปใส่ที่ Environment variables ของ Netlify

**3. ผูกร้าน** — เปิด `/api/setup/tiktok?key=SYNC_SECRET` หนึ่งครั้ง
(ใช้โทเคนเดิมจาก Colab ไม่ได้ทำ OAuth ใหม่ จึงไม่ไปล้มของเดิม)

**4. ดูออเดอร์** — เปิด `/orders` แล้วกด "ดึงออเดอร์ตอนนี้"
Netlify จะดึงให้เองทุก 5 นาที (ตั้งไว้ที่ `netlify.toml`)

## โครง

| ไฟล์ | ทำอะไร |
|---|---|
| `lib/tiktok.js` | เซ็นคำขอ + ดึงออเดอร์ (search ได้ id → ตามด้วย orders?ids= เพื่อเอารายการสินค้า) |
| `lib/status.js` | แปลงสถานะของแต่ละแพลตฟอร์มให้เป็นสถานะกลาง |
| `lib/ingest.js` | เขียนลง `os_orders` / `os_order_items` |
| `lib/tokens.js` | อ่านโทเคนจาก DB + ต่ออายุอัตโนมัติเมื่อใกล้หมด |
| `app/orders` | หน้าตารางออเดอร์ แยกตามสถานะ |
| `app/api/sync/tiktok` | รอบดึงข้อมูล (ปุ่มบนเว็บ หรือ cron ยิงมาพร้อม `?key=`) |

## ⚠️ เรื่องโทเคนชนกับ Colab

สคริปต์ `sync_stock_all_platforms_v7.ipynb` ใช้ **แอปตัวเดียวกัน** และ refresh โทเคนทุกครั้งที่รัน
TikTok เปลี่ยน refresh_token ใหม่ทุกครั้งที่ต่ออายุ — ถ้าทั้งสองฝั่งต่างคนต่าง refresh จะแย่งกันจนพัง

ระหว่างที่ยังใช้ Colab อยู่ ให้เลือกทางใดทางหนึ่ง:
- ตั้ง cron ของเว็บให้ห่างจากเวลารัน Colab และคอยดู `os_sync_log` ว่าพังไหม
- หรือขอ **แอปใหม่ใน Partner Center** สำหรับเว็บโดยเฉพาะ แล้วต่างคนต่างมีโทเคนของตัวเอง (ปลอดภัยสุด)

## หน้า "เงินเข้า" (`/money`)

ตอบคำถาม: **ขายราคาป้ายเท่าไร ร้านลดไปเท่าไร โดนหักเท่าไร เหลือเข้ากระเป๋าเท่าไร**
`os_orders.total` คือยอดที่ลูกค้าจ่าย ไม่ใช่เงินที่เราได้

| ไฟล์ | ทำอะไร |
|---|---|
| `supabase/014_money_statements.sql` | ตาราง `os_statements` (ใบสรุปรายวัน) + `os_money_tx` (รายออเดอร์) + ตัวสรุปยอด — แทนที่ 013 |
| `lib/tiktok.js` | `listStatements` / `getStatementPage` / `normalizeMoneyTx` |
| `lib/settlement.js` | บันทึกลงตาราง + ชื่อไทยของค่าธรรมเนียมแต่ละตัว |
| `app/api/sync/settlement` | รอบดึง (ปุ่มบนเว็บ หรือ cron รายชั่วโมงพร้อม `?key=`) |
| `app/api/debug/settlement` | ส่องก้อนดิบ + ตรวจสมการของแต่ละรายการ |
| `app/money` | หน้าเว็บ |

**ดึงตาม "ใบสรุปรายวัน" ไม่ใช่ถามทีละออเดอร์** — รุ่นแรก (013) ถามทีละใบ ร้านปิดยอดวันละ ~500 ใบ
แต่ Netlify ให้เวลา ~26 วินาทีต่อรอบ ได้แค่ ~40 ใบ และโดนตัดก่อนบันทึกทุกรอบ
ใบสรุปดึงได้ครั้งละ 100 รายการ วันละ ~5 ครั้งก็ครบ รอบถูกตัดกลางทางก็ทำต่อจาก `cursor` ที่จำไว้

**ใช้ statement_transactions เวอร์ชัน 202501** — 202309 แจกแจงค่าธรรมเนียมไม่ครบ
(ใบตัวอย่างหัก 86.62 บอกที่มาได้แค่ 48) ตรวจ 202501 กับข้อมูลจริง 100 รายการ
สมการ `revenue + fee + shipping + adjustment = settlement` ตรงทุกรายการ

**ออเดอร์ที่เพิ่งสั่งจะยังไม่โผล่** — TikTok ปิดยอดหลังของถึงมือ + พ้นเวลาคืนของ ปกติ 10-20 วัน

**ยังไม่รองรับ:** Shopee (`payment/get_escrow_detail`) และ Lazada — คนละ API กัน ต่อทีหลัง
